## 2. Architecture (back-end)

- 17 contrôleurs publics, 23 Actions, 24 DTO `final readonly`, 18 helpers `Support`. Les contrôleurs délèguent, sauf `BuyController::facts()` (logique + lecture brute de `ui.php`) et `ContactController::prefill()` (25 lignes, `app(ShowProperty::class)` au lieu de l'injection). `HomeController` lit `ui.about.stats.1.value` par index.
- Couplages inter-contextes passant par des Actions publiques : conformes. `LocalizedUrls` est un singleton muté par `override()` : correct sous FPM, fuite sous Octane.
- Quatre implémentations du formatage de prix côté PHP (`ListStats`, `BuyController`, `PropertySeo::number`, `ValuationRequestMail`) et une en JS : un helper unique s'impose.
- `GOOGLE_MAPS_API_KEY` exposé sous deux clés de config (`services.google_maps`, `seo.google_maps`).
- Ordre des middlewares correct : `trustProxies` → `CanonicalUrl` → `SecurityHeaders`. Throttle par IP sur les quatre POST. `config:cache` et `route:trans:cache` compatibles.
- `ResilientHttpGateway` avale toute exception sans `report()` : un SSR qui tourne mais plante est invisible dans les logs. `SendContactMessage` logue sans `report()`, contrairement à `SendValuationRequest`.

## 4. Sécurité

- **[fait]** redirection ouverte, 500 sur paramètres en tableau, en-têtes de sécurité (middleware du 11 octobre).
- Mass assignment maîtrisé (`$fillable` explicites, remplissage depuis les DTO), FormRequests avec honeypot, longueurs et `Rule::in`, `hash_equals` pour le code off-market, un seul `{!! !!}` sur une traduction statique, sujets de mail neutralisés par Symfony Mailer.
- À traiter : avis `composer audit` / `npm audit` ; code off-market à 6 chiffres limité à 5 essais par minute et par IP (7 200 par jour, rotation d'IP possible) : limiteur global ou verrouillage ; `trustProxies('*')` suppose que seul le load balancer Cloud atteint l'application ; pas de CSP (GTM, Maps, YouTube à lister en mode rapport).

## 5. Conformité à `CLAUDE.md`

- Tiret demi-cadratin : zéro violation hors l'exception `SeoText`. Fichiers kebab-case, composants PascalCase, pas de hex ni de `rounded-*` ni d'ombre sur le site public, icônes Lucide seulement, aucun texte en dur, aucun `href="#"`, aucun TODO.
- Écarts : `--card-h` en `style` dans `about-hero.tsx` ; six `transition-*` sans `motion-reduce:` (chevrons de la galerie, switcher, menu) ; `team-grid.tsx` et `map-preview.tsx` sans `srcSet` ; `composer run check` appelle `eslint --fix` et peut donc modifier l'arbre ; `exhaustive-deps` en warn.
- i18n : 34 chaînes FR citent encore la marque, dont deux surtitres « Pourquoi Estate in Paris » et le thème FAQ « Travailler avec Estate in Paris », à arbitrer ; quelques libellés identiques FR/EN suspects (`stories.eyebrow` « Success story » côté FR, « Arrondissements » en EN).
- SEO : titres 20-60 et descriptions 120-160 partout, aucun doublon ; `/recherche` dans le sitemap en 0.8 alors qu'elle tourne sur un jeu factice ; lien « Plan du site » émis deux fois dans `llms.txt`.
- Documentation : `CLAUDE.md` annonce « 36 tests PHPUnit » (202 réels), décrit encore le title en suffixe ` · Estate in Paris` et `withSuffix` (préfixe et `withBrand` depuis le 11 octobre), omet vitest dans `composer run check`, cite sept chemins disparus (`language-switcher.tsx` à la racine, `brand-logo.tsx` à la racine, `footer/newsletter-signup.tsx`, `i18n/flag.tsx`, `sell-photo.tsx` et son test, `sell-gallery`, route `terms`), `SEO_SOCIAL_INSTAGRAM` et Node 20.

## 6. Tests

- 202 tests PHP (47 fichiers), 267 tests JS (90 fichiers), `tsc` et ESLint propres.
- Manques : cache de `SanityClient` (TTL, hit, échec non mis en cache), middleware `NoSsr`, pages d'erreur 403/500/503 et 419, échec du mail de confirmation contact, `prefill` contact avec un slug inconnu ou off-market, précédence de `LocalizedUrls::override`, 301 de `PropertyController` sur un mauvais segment.
- Fragilités : appels réseau réels (point 1), tests qui écrivent `public/sitemap*.xml`, plusieurs tests qui lisent `ui.php` plutôt que d'exercer un comportement (utiles comme lint de contenu).

## 7. Plan proposé

1. Dépendances : `composer update` et `npm audit fix`, vérification complète, build SSR.
2. Tests hermétiques : `Http::preventStrayRequests()`, fake Sanity, sitemap sur un disque de test.
3. Front : drapeaux statiques, sélecteur de téléphone en `React.lazy`, formateur de nombres par locale, `motion-reduce` manquants, timers, code mort.
4. Serveur : mails en file d'attente, cache Sanity long + rafraîchissement planifié + cache négatif, `ListBuyFacts` et un formateur de prix unique, mémo de `ListProperties`, `report()` dans le gateway SSR.
5. Médias : ré-encodage des clips, posters WebP, suppression des orphelins et des doublons.
6. CI : `composer run check` + `build:ssr` en mode vérification, Node épinglé.
7. `CLAUDE.md` : corriger les quatorze écarts listés en section 5.
